# SwftSwap — ERC-7730 spec limitations

## Amount denominated in a token named only by a string
- **What the signer should see:** `minReturnAmount` as a scaled amount with its ticker, e.g. `107.859983 USDT (TRON)` or `93.148668 USDT (BSC)`, so the requested payout can be compared with the amount sent.
- **What the spec cannot express:** `Field formats > tokenAmount` resolves the ticker and decimals only from an address (`tokenPath` or `token`, optionally with `chainId` / `chainIdPath`). Here the destination token is a string argument (`toToken`, e.g. `USDT(TRON)|…`) that names a token on another chain, often a non-EVM one (TRON). `Field formats > unit` needs a fixed `decimals`, but the decimals change with the destination token (6 on TRON, 18 on BSC in the real transactions). No format can take decimals or a ticker from another field or from a string.
- **Workaround in this descriptor:** `minReturnAmount` is shown with `format: "raw"` under the label `Requested Minimum`, placed last so the integer is not read as an amount of the sent token; the sentence says "requested minimum {minReturnAmount}".
- **Proposed spec improvement:** extend `tokenAmount` (or `unit`) with `decimalsPath` and `tickerPath` parameters that read the decimals and the ticker from other fields, with `tickerPath` allowed to point at a `string` argument (optionally with a `tickerRegex`/`tickerSlice` to extract the symbol from a packed string). Alternatively allow `tokenPath` to resolve through a `$.metadata.tokens` map keyed by string symbols with declared decimals.

## No way to state that a value is a request the contract does not enforce
- **What the signer should see:** a short notice that the payout is made off-chain by SWFT from its own funds, that `minReturnAmount`, `toToken` and `destination` are only logged (never checked by the contract), and that the deposit has no on-chain refund path or deadline.
- **What the spec cannot express:** `Display Formatting > Format Specification` offers `intent`, `interpolatedIntent` and field `label`s as the only free text, all meant to be short; there is no per-format or per-field notice/caveat that a wallet must show, and `visible`/`mustMatch` cannot encode "logged but not enforced".
- **Workaround in this descriptor:** the intent says `Send to SWFT for swap` (naming the counterparty rather than claiming a swap), the minimum is labelled `Requested Minimum` and the sentence avoids "at least"; the trust assumption is stated in REPORT.md for the reviewers, not for the signer.
- **Proposed spec improvement:** an optional `notice` string on a format (and on a field) that wallets MUST display before the fields, intended for trust assumptions such as "Paid out off-chain by SWFT; the minimum is not enforced by this contract", with a length limit so that constrained devices can show it.
