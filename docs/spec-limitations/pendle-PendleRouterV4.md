# Pendle RouterV4 — ERC-7730 spec limitations

## Token that only an on-chain read of another argument can name
- **What the signer should see:** the PT, YT or SY amount with its ticker and decimals, for example "Sell 86409.61 PT-apxUSD-5NOV2026". The calldata names the market, not the PT, YT or SY. The router reads these tokens with `IPMarket(market).readTokens()` (ActionSwapPTV3.sol:25,62; ActionSwapYTV3.sol:30,70; ActionAddRemoveLiqV3.sol:28,57,86) or `IPYieldToken(YT).SY()` (ActionMiscV3.sol:61).
- **What the spec cannot express:** "Field formats > tokenAmount" takes `token` (a constant, which may be a map reference) or `tokenPath` (a path into the calldata or container). Nothing in the spec says "the token is the second return value of `readTokens()` on the address at `market`".
- **Workaround in this descriptor:** `metadata.maps` holds `marketPt`, `marketYt` and `marketSy` (664 markets each) and `ytSy` (639 YTs), built from every `CreateNewMarket` log of Pendle's market factories and a `readTokens()` call on each market, expired markets included. The amounts use `"token": {"map": "$.metadata.maps.marketPt", "keyPath": "market"}` and the like. The values never change, because PT, SY and YT are immutables in the market. But the map is a snapshot: a market created later is not in it, and the spec ("metadata.maps") makes the descriptor invalid for that transaction, so it is blind until the map is refreshed. Pendle created 37 markets in the 90 days before the snapshot. Other costs: the maps make the descriptor 392 KB; python-erc7730 drops map references when it converts for Ledger; the Rust reference runner does not parse spec map references.
- **Proposed spec improvement:** a `tokenFrom` parameter for `tokenAmount` that names a view call on an address path with a return index, for example `{"tokenFrom": {"targetPath": "market", "function": "readTokens()(address,address,address)", "index": 1}}`. Wallets that cannot run the call fall back to raw. This would remove the snapshot, the refresh duty and the size cost. A smaller step: let a map declare a fallback (for example `"onMissing": "raw"`) instead of making the descriptor invalid, so that a new market renders raw instead of blind.

## Amount known only at execution, reported by caller-named contracts
- **What the signer should see:** in `redeemDueInterestAndRewardsV2`, the amount of each reward token that the router will swap, together with the swap minimum.
- **What the spec cannot express:** the amount is not in the calldata. It is the sum that the SY, YT and market contracts named in the arguments report from their claim calls (ActionMiscV3.sol:144-159, 334-346). The router then pulls that sum from the signer (:161-163). The spec has no "amount determined at execution" marker, and no way to bind a list of addresses to a trusted set without hiding the list.
- **Workaround in this descriptor:** the screen shows which token each swap sells and its minimum output (enforced at :369-370), plus the claimed SYs, YTs and markets as tickers. It shows no input amount. The minimum-interest check is enforced by `yt.SY()` of the named YT (ActionBase.sol:107).
- **Proposed spec improvement:** a `visible: {"mustBeIn": "$.metadata.maps.<name>"}` rule that keeps a field visible but makes the descriptor invalid when the value is not a key of the map (for example, `YTs.[].yt` would have to be a known Pendle YT), and an `amountUnknownUntilExecution` marker that tells wallets to say so next to the token.

## Token of an amount that depends on another argument's value
- **What the signer should see:** "Minimum to Receive" in the token that the receiver actually gets. In `TokenOutput` that token is `tokenRedeemSy` when `swapData.swapType` is NONE (the SY pays the receiver directly, ActionBase.sol:73-74). With any other swap type (ETH/WETH wrapping or an aggregator route) it is `tokenOut` (ActionBase.sol:75-89). The check `netTokenOut < out.minTokenOut` applies in both cases (ActionBase.sol:91).
- **What the spec cannot express:** "Field formats > tokenAmount" takes a single `tokenPath`. "Field format specification > visible" has only `ifNotIn` and `mustMatch`, each on one field. No construct picks a `tokenPath` by the value of another field, and no rule requires two fields to be equal (`tokenOut == tokenRedeemSy`).
- **Workaround in this descriptor:** `output.swapData.swapType` is pinned with `mustMatch: [0]` and the minimum is denominated in `tokenRedeemSy`. With that pin, the screen is true for any value of the other arguments. Exits with any other swap type are refused for clear signing. In 1 day and 19 hours of mainnet traffic (blocks 26278332–26291422) this was 59 of 167 successful `TokenOutput` calls.
- **Proposed spec improvement:** A conditional parameter, e.g. `"params": {"tokenPath": {"switch": "output.swapData.swapType", "cases": {"0": "output.tokenRedeemSy"}, "default": "output.tokenOut"}}`. A simpler alternative is a cross-field visibility rule such as `"visible": {"mustEqualPath": "output.tokenRedeemSy"}`, so that a descriptor can show `tokenOut` and refuse calls where the two tokens differ.

## Nested call that the intermediary rewrites, or that is calldata only for some values of another field
- **What the signer should see:** the aggregator call that PendleSwap makes, with its real amounts, and the call that `callAndReflect` reflects.
- **What the spec cannot express:** the `calldata` format (Field formats > calldata) assumes the bytes are executed as written. PendleSwap rewrites the amounts when `needScale` is true (`PendleSwap.sol:43`). The Reflector replaces the input amount with its own balance (`Reflector.sol:90,102`). For 0x routes the bytes are `abi.encode(...)` and not calldata (`PendleSwap.sol:57-59`). The value is `amountIn` only when the input is native (`PendleSwap.sol:44`). The format has no condition on another field and no "arguments overridden" marker.
- **Workaround in this descriptor:** `input.swapData.extCalldata` has the `calldata` format but stays hidden. The router's final minimum check protects the signer. `callAndReflect` is excluded.
- **Proposed spec improvement:** a `calldata` parameter `when` (a condition on another path, for example the swap type), and an `argumentsOverriddenBy` marker that tells wallets to show the call's target and selector but not its amounts.
